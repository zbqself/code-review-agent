# Python 代码规范

## 异常处理

- 禁止使用裸 `except:`，它会吞掉包括 `KeyboardInterrupt`、`SystemExit` 在内的所有异常。
  至少写成 `except Exception:`，并记录日志。
- 捕获异常后不要静默 `pass`，要么处理、要么重新抛出、要么记录原因。
- 不要用异常做正常流程控制；先判断条件（如 `if key in d`），而不是靠 `try/except` 兜底。

## 可变默认参数

- 函数默认参数禁止使用可变对象（空列表、空字典、空集合）：
  `def f(items=[])` 是错误的，因为所有调用会共享同一个列表对象。
  应该写成 `def f(items=None)`，然后在函数体内 `if items is None: items = []` 初始化。

## 路径与资源

- 读写文件统一使用 `pathlib.Path`，不要用字符串拼接路径。
- 打开文件用 `with open(...)` 确保关闭；读取外部输入务必显式指定 `encoding` 并做异常处理。
- 数据库连接、网络连接、文件句柄等资源都要用 `with` 或 `finally` 释放。

## 类型与风格

- 公开函数建议写类型注解和 docstring。
- 遵循 PEP 8：行宽建议不超过 100 字符，命名用小写下划线。
- 避免过深的嵌套（一般不超过 3~4 层），复杂逻辑抽成小函数。

## 性能

- 频繁查询的成员用 `set`/`dict` 而不是 `list`，把 O(n) 降到 O(1)。
- 拼接大量字符串用 `"".join(parts)`，不要用 `+` 循环累加。
- 大文件/大列表用生成器或分页处理，避免一次性全部加载进内存。

## 并发

- 共享可变状态要加锁（`threading.Lock`）或使用 `queue.Queue` 等线程安全结构。
- 多线程里的“检查-再执行”不是原子的，必须加锁或用 `with lock:`。
- 不要在持有锁的时候做耗时 IO 或调用可能再抢锁的函数，避免死锁。

## 测试

- 关键逻辑要有单元测试，覆盖正常路径、边界和异常路径。
- 对外部依赖（网络、数据库）做 mock，让测试可重复、可离线运行。
