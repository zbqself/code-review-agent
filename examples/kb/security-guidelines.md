# 安全编码规范

## 注入

- SQL 必须用参数化查询或 ORM 的绑定参数，禁止拼接字符串（防 SQL 注入）。
- 拼接命令时避免直接拼用户输入；命令执行优先用参数列表而不是 shell 字符串。
- 输出到网页要做转义/编码，防 XSS。

## 敏感信息

- 密码、密钥、token 禁止硬编码进源码或配置文件；用环境变量或密钥管理服务。
- 日志里不要打印密码、token、身份证号等敏感字段，打印前脱敏。
- 不要把真实密钥提交进 git 仓库；`.env` 等敏感文件加入 `.gitignore`。

## 鉴权与授权

- 每个需要权限的接口都要做鉴权和授权校验，不能只靠前端隐藏按钮。
- 越权风险：操作资源前校验“当前用户是否拥有该资源”，不要只校验是否登录。
- 使用成熟的密码哈希算法（如 bcrypt、argon2），禁止明文或 MD5 存密码。

## 输入校验

- 所有外部输入（HTTP 参数、文件内容、第三方返回）都要校验长度、类型、格式。
- 文件上传要校验文件类型、大小，并对内容做检查，不能只信扩展名。
- 反序列化不可信数据要谨慎（避免反序列化漏洞）。

## 依赖与配置

- 定期检查依赖漏洞（如 pip-audit、npm audit），及时升级有漏洞的版本。
- 生产环境关闭调试接口、详细错误堆栈，避免泄露内部实现。
